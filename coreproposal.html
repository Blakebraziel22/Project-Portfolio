B2B Self-Service Core Pickup Request & Automated ERP/ION App Lifecycle Architecture

Executive Summary: This specification details the technical architecture and business rationale for introducing a digitized **Self-Service Core Pickup Request** module within the B2B E-Commerce Portal ("My Account"). By providing customers with a streamlined request form and real-time core ledger, form submissions directly generate NetSuite Sales Orders using a dedicated non-inventory item (`pickup-only`) and custom Analysis Code. This insulates E-Commerce P&L from branch-level core credit liabilities while fully automating driver pick-tickets, ION App logistics logging, and Phase 2 NetSuite Credit Memo visualization.

1. Strategic Objectives

  • Eliminate Operational Friction: Replace manual phone calls, rep texts, and paper notes with an automated, self-service request module accessible 24/7 in the B2B Portal.
  • Insulate E-Commerce Financial Obligations (P&L Protection): Apply a dedicated NetSuite Analysis Code to all self-service core pickup requests, ensuring the digital channel facilitates logistics without absorbing branch-managed financial liabilities or credit adjustments on E-Commerce P&L reporting.
  • Digitize Branch & Driver Fulfillment Workflows: Automatically queue pickup requests as branch pick-tickets, feeding directly into route management and the driver **ION App** for seamless physical battery pickup logging.
  • Auditability & Credit Visibility (Phase 2): Provide commercial buyers with full visibility into request history, actual units received, and direct links to generated NetSuite Credit Memo PDF documents.

2. B2B Portal User Interface & Form Specification

Module Placement & Tabbed Navigation Structure

The feature resides in the left-hand navigation sidebar under "Core Pickup Request" (with a highlighted NEW badge) and utilizes a 2-tab view layout:

  • Tab 1: Request Core Pickup (Default Landing): Features static operational disclaimers, pickup location selection, unit quantity controls, and optional internal reference inputs.
  • Tab 2: Core Request History (Ledger View): Displays a structured ledger tracking all past requests, pickup statuses, fulfilled quantities, and hyperlinked NetSuite Credit Memos.
Static Header Operational Disclaimer
"Please note, your servicing branch will arrive on your regular scheduled delivery date. To request a core pickup, please select how many cores you have, and which location they will be picked up from."

Form Validation & Input Parameters

  • Pickup Location Selector: Dropdown search populating the customer's authorized child ship-to locations. Auto-prefills if the account maintains only one location.
  • Minimum Quantity Threshold: Strict client-side and server-side validation enforcing a minimum of **10 cores** per request to optimize route logistics efficiency.
  • PO / Reference Memo Field: Optional free-text field allowing customers to enter internal POs or reference past Continental Invoice #s (e.g., cross-referencing invoice lines where cores were previously unreturned).

3. End-to-End Technical Workflow & System Integration

Form submission bypasses standard cart/checkout screens to maintain a frictionless service request experience:

[Customer Submits Core Request Form (Qty >= 10, PO/Memo, Location)] │ ▼ [Magento Bypasses Cart/Checkout & Triggers Direct Sales Order Generator] │ ├─ Appends Custom P&L Analysis Code: ANALYSIS_CORE_SERVICE_ONLY │ └─ Injects Non-Inventory Line Item: SKU "pickup-only" (Qty = Requested) │ ▼ [NetSuite Ingests Sales Order & Renders Branch Pick-Ticket] │ ▼ [Branch Route Manager Schedules Driver Delivery Day Pickup] │ ▼ [Driver Collects Cores & Finalizes Transaction via ION App] │ └─ Logs Exact Used Battery Quantities & Core Charge Types │ ▼ [NetSuite Generates Final Credit Memo (CM-XXXXX)] │ ▼ [Inbound Sync to Magento Portal (Phase 2 Integration)] │ └─ Links Credit Memo PDF & Final Received Qty to Magento Order ID │ ▼ [Core Request History Tab Updated: Status = "Completed"]

4. Technical Specifications & Financial Rules

System Configuration & ERP Parameter Rules

  • Non-Inventory Item Placeholder: Utilizes a dedicated ERP SKU (pickup-only). This generates a zero-dollar or placeholder blended fulfillment line required for pick-ticket printing and warehouse visibility without impacting commercial product inventory levels.
  • Financial Analysis Code Isolation: Orders created via this module carry an isolated Analysis Code (e.g., ECOMM_CORE_SVC). This tag signals financial reporting scripts to route all resulting credit memo adjustments back to the servicing branch's operational ledger, maintaining **E-Commerce P&L Neutrality**.
  • Phase 2 Credit Memo Synchronization: Leverages the "Magic Button" Credit Memo portal integration framework. Once NetSuite finalizes the core credit, Magento ingests the Credit Memo ID, actual received unit count, dollar amount, and PDF document link, mapping them directly to the original Magento Order ID in the ledger.

6. Financial ROI & Operational Leverage Metrics

Executive Key Performance Indicators (KPIs) & Value Drivers

  • Branch Administrative Cost Reduction: Eliminates manual phone call/email intake, saving an estimated 10–12 minutes of branch rep labor per request (~$50,000+ annually across nationwide distribution centers).
  • Accelerated Core Capital Velocity: Digitizing and enforcing minimum pickup thresholds (10+ units) speeds up core return cycles, accelerating recycling turnaround and unlocking branch capital bound in uncollected customer core liabilities.
  • Zero E-Commerce P&L Distortion: Custom NetSuite Analysis Code routing ensures digital adoption KPIs grow without incorrectly saddling the e-commerce department with branch-managed core credit liabilities.
  • 100% Billing & Collection Accuracy: Tying the digital request ID through to the driver’s **ION App** prevents manual core count discrepancies, reducing invoice disputes and customer service escalation volume by an estimated 40%.
