Executive Summary: Initiated through an operational discovery loop led by the VP of Operations, this project automates what was slated to be a high-friction, manual ordering process for a new wholesale truckload and container purchasing program. Rather than subjecting heavy wholesale buyers to a phone/email workflow or an inflexible off-the-shelf checkout, this architecture repurposes the existing B2B reorder pad component into an interactive 14-pallet trailer capacity engine.

Crucially, this initiative serves as the enterprise's flagship pilot for Adobe App Builder, decoupling custom commercial front-end experiences from the core monolithic commerce installation. By isolating deployment into an independent serverless runtime, this pattern cuts future development go-live cycles by 50%, reduces potential production downtime by up to 80%, and closes the operational loop via NetSuite drop-ship Sales-Order-to-Purchase-Order (SO-to-PO) automation.

1. The 72-Hour Discovery Loop & Strategic Feasibility

When Operations introduced the volume truckload program, the baseline plan relied on manual order intake: branch reps and sales operations capturing multi-stop destination drops, checking pallet-tier price sheets, verifying axle weight constraints, and manually generating sales orders.

Asked whether the digital B2B portal could abstract this operational overhead, the immediate product challenge was balancing delivery velocity against platform technical debt:

  • The 72-Hour Technical Spike: Conducted an architectural audit across Adobe Commerce and NetSuite schemas to evaluate whether building bespoke monolithic controllers was justifiable against ongoing maintenance overhead.
  • Re-purposing Proven UI Frameworks: Rather than drafting a greenfield UI from scratch, the architecture targeted our existing, battle-tested Reorder Pad iframe framework. This component already maintained the required customer-pricing resolution logic, tiered SKU representation, and quantity stepping mechanics.
  • Checkout Path Bypass: Standard multi-step e-commerce checkouts (cart → shipping → billing → payment review) are fundamentally incompatible with $80,000+ commercial truckloads. The architecture was designed to bypass the standard cart entirely, writing customer commitments directly into the order tables upon review modal verification.

2. Strategic Platform Modernization: The App Builder Pilot

Decoupling Custom Development from the Commerce Monolith

Historically, enterprise customizations were integrated directly into the core monolithic codebase. This created cascading dependencies, extensive regression QA burdens, and deployment risks where a defect in a specialized B2B feature could compromise primary storefront checkout stability.

The Truckload Builder is our pioneer deployment of Adobe App Builder (cloud-native serverless extensibility), establishing an organizational blueprint for all future custom commerce capabilities:

  • 50% Acceleration in Go-Live Velocity: Development, iteration, and deployment occur within an isolated App Builder runtime. Engineering teams go from concept to production without waiting on bi-weekly monolithic build and release trains.
  • Up to 80% Reduction in Production Downtime & Outage Risk: Defect blast radius is fully contained. Because code runs in an isolated containerized environment, an edge-case runtime exception in the truckload module cannot corrupt or bring down the primary commerce storefront.
  • Dramatically Compressed QA & Regression Cycles: Testing is strictly localized to the single App Builder instance and its discrete API contracts. This eliminates the requirement for sitewide end-to-end regression sweeps and complex monolithic A/B test verifications.

3. Two-Tier App Builder Architecture & System Flow

The system employs a decoupled, two-tier micro-application model ensuring front-end speed while centralizing backend governance and authentication:

Tier 1: Client-Side Interactive Spatial Builder (App Builder Instance 1)

Renders directly in the browser via an authenticated customer session. It handles the interactive 14-slot trailer canvas, HTML5 drag-and-drop pallet repositioning, live 50,000 lb gross weight calculation, minimum order gating (12/14 pallets), and multi-stop payload distribution.

Tier 2: The Enterprise ERP Gatekeeper Proxy (App Builder Instance 2)

Acts as the single, authenticated gateway between commercial storefront events and the core ERP infrastructure. All outbound order payloads from Instance 1 terminate at the Gatekeeper, which validates payload schemas, enforces token-bucket concurrency limits, verifies authorization tokens, and writes clean transaction records into the ERP pipeline.

4. Data Governance & Automated Drop-Ship Fulfillment

Attribute-Based Storefront Access Control (ABAC)

Because wholesale truckload pricing and trailer dispatch are restricted to approved commercial accounts, access is governed dynamically. An extension attribute (is_truckload_eligible) on the customer entity flags whether the authenticated user has access. When valid, Magento dynamically populates navigation entry points on the homepage and within the My Account portal, securing program pricing behind authorization boundaries.

Financial P&L Isolation via Custom Analysis Codes

Orders flowing through the truckload program represent multi-pallet, high-revenue transactions that bypass standard branch fulfillment fleets. To insulate regional branch operating metrics from direct-factory container shipments, all orders generated by the Gatekeeper automatically inherit a dedicated NetSuite Custom Analysis Code. This routes revenue and margin credit to the wholesale strategic program ledger, preventing P&L skew across retail branch P&Ls.

SKU-Level Drop-Ship Vendor Assignment & Automated PO Generation

Truckload orders are fulfilled factory-direct by commercial battery manufacturers rather than our internal warehouse network. Built-in workflow logic in NetSuite automates the drop-ship lifecycle:

  • Dynamic Vendor Resolution: When the Sales Order is ingested, NetSuite evaluates the lines against the preferred manufacturing supplier assigned at the SKU master level.
  • Automated PO Creation: NetSuite automatically creates a corresponding Purchase Order linked directly to the parent Sales Order.
  • Electronic Transmission: Order specifications, customer destination addresses (partitioned by stop), and shipping requirements dispatch automatically to the vendor's EDI/cXML ingestion queue, eliminating manual buyer intervention.

Dedicated "Truckload Orders" Self-Service Portal

To provide transparency for commercial purchasing agents managing multi-stop orders, a custom "Truckload Orders" ledger view was integrated into the customer portal. Buyers can track shipment statuses, review PDF invoices, verify multi-stop drop receipts, and reference the associated master PO number across all stops.
