B2B DoorDash Program Architecture: Multi-Location Address Mapping & Header Location Switcher

Executive Summary: This updated architecture specification details the implementation for enabling same-day DoorDash delivery across multi-location B2B accounts. To account for single-user logins managing multiple child accounts and distinct servicing branches, branch assignment is moved to the Address Entity Level in Magento. Furthermore, we repurpose our existing B2C "My Store" header selector to allow buyers to switch active shipping locations during browsing, dynamically evaluating local branch stock without NetSuite API performance penalties.

1. Strategic Objectives

  • Neutralize Competitor Schedules: Target the primary weakness of key competitors (e.g., Interstate Batteries) who rely exclusively on fixed, scheduled weekly route trucks by offering 45-minute local emergency dispatch.
  • Drive Portal Customer Retention ("Stickiness"): Lock in commercial service centers and dealers by making our portal their primary emergency "line-down" battery source.
  • Break-Even Cost Model: Treat local courier delivery as a service feature priced at a flat break-even rate ($20 / $40), capturing profit purely through battery unit margin and sustained account loyalty.
  • Support Enterprise Multi-Location Buyers: Enable single buyers who manage multiple child accounts/ship-to locations to seamlessly check DoorDash stock and place express orders across different servicing branches.
  • Zero NetSuite Overhead / Rate Limit Prevention: Use Magento's local database and Multi-Source Inventory (MSI) to evaluate stock locally, eliminating API calls to NetSuite during page browsing.

2. B2B Frontend Experience & Location Selector

Repurposing the B2C "My Store" Selector for B2B

On our B2C site, we currently utilize a "My Store" location selector. We will adapt this existing UI component for the B2B Portal:

  • Header Component: Displays in the portal header as "Shipping To: [Active Branch/Address Name]".
  • Address Book Population: Instead of querying public retail stores, the dropdown queries the logged-in user's authorized B2B Company Address Book (child ship-to locations).
  • Active Context Session: When selected, Magento updates the active session parameter active_ship_to_address_id.

PLP & Search Page Eligibility Rules

Given a B2B user is browsing a PLP or search results page,
When an active location is selected AND the item is in stock at the branch mapped to that location in Magento MSI,
Then display an inline badge: ⚡ Eligible for DoorDash Same-Day Delivery.

Cart & Checkout Re-Evaluation Logic

When a user selects or modifies their Ship-To address in checkout, Magento triggers its native shipping rate estimation workflow:

[User Selects Ship-To Address at Checkout] │ ▼ [Retrieve Address Attribute: assigned_branch_source_code] (Internal Magento Query) │ ▼ [Query Magento Local MSI Stock for Assigned Branch] │ ├──> All Cart Items In-Stock & Cart Weight <= 300 lbs ──> RENDER DoorDash ($20 / $40) └──> Any Item Out-of-Stock OR Cart Weight > 300 lbs ───> HIDE DoorDash Method

3. Technical Architecture: Address-Level Branch Mapping

Magento Address Entity Extension Attribute

To support multi-location child accounts, branch mapping is placed on the Company Address / Customer Address entity rather than the parent company record.

  • Custom Extension Attribute: assigned_branch_source_code on Magento\Customer\Api\Data\AddressInterface.
  • Data Sync: When NetSuite syncs child accounts and ship-to addresses into Magento, each address carries its specific NetSuite Servicing Branch ID (e.g., Houston Ship-To → SRC_HOUSTON, Dallas Ship-To → SRC_DALLAS).
  • Default Behavior: If a user has one location (ship to address), then that address will be prefilled in the header selector. If a user has multiple locations, the selector will be outlined in bold red and empty, and the active branch assignment remains NULL until a location is chosen.

To protect courier driver safety and avoid order cancellations, disclaimers render dynamically at checkout based on total weight:

"Flat fee of $20 up to [XX] miles. Servicing branch loads delivery vehicle. Customer is required to unload batteries upon arrival."

  • Customer Bay Savings: Eliminates $1,200+ in lost billable labor per incident for dealer service centers waiting on weekly competitor route trucks (Interstate).
